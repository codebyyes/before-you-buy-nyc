## 做事之前先知道四件事

**一、802 用 iPad，沒有電腦，不懂程式。** 他貼不了長程式碼。
流程是：你推 GitHub → 他在 Replit Agent 對話框貼一行指令拉下來。
指令原文在 `state-2026-10-11.md`。給他的步驟要像教幼稚園，一次一步。

**二、你連不到線上網址、NYC Open Data 和 Tavily。** 容器的連外白名單擋掉了。
本地只能用 stub 測（`scratchpad/serve_full.py`），線上只能靠 802 截圖。
別浪費時間試。

**三、「不要直接做先跟我說」。** 802 說了至少四次。
**他要的是先看到你的判斷，再決定要不要做。** 做完才講等於剝奪他決定的機會。

**四、只有你看得見的選項，必須主動攤開給他。**
**這是規則，不是那四個例子。** 判準是：**只要有一個選擇是他從介面上看不見的，
就先講。** 10/11 犯了四次（Explorer 沒收到上下文、抽日期沒收到關鍵字、
查詢語言、只開布魯克林還是五區），但那是例子不是清單。他不懂程式，
**不是不懂取捨**。一行就能改的事不要替他決定。

**五、說「缺了什麼」之前，先自己打開檔案看。**
10/11 晚上照搬交接文件寫的「README 等於沒寫」，結果 README 有安裝說明，
真正缺的是三個環境變數。802 當場指出來，而且他是對的。

同一晚還有一次：反對一件事時堆了三個理由（內容風險 + 是新功能 + 快截止了），
802 問「我們有開發什麼新功能？」——我們沒有。**一個論點要靠堆才站得住，
通常表示對它沒把握。** 給一個站得住的理由就好。

## 七條不能動的規則

在交接文件裡。最常被「好心」改掉的四條先列在這：

1. **用「之後」不用「造成」** —— 不是文字風格，是原則
2. **AI 絕對不碰數字** —— 房價變化由程式從官方資料算，模型拿不到價格
3. **空結果是正確的結果** —— 但只有「查過了、真的沒有」（`NO_EVIDENCE`）才算。
   查不成、額度沒了、超出可測範圍、被閘門擋下，**都不是空結果**
4. **閘門擋下東西不是故障** —— 文案不准道歉。`test_explorer.py` 在掃這件事
